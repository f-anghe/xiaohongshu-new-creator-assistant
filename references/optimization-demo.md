# 优化 Demo 生成模块

## 输入

进入本模块前，必须先收齐三项用户输入：覆盖完整内容的作品截图（多图需全部上传）、对应的笔记数据截图、本轮优化目标。缺少任一项时停留在输入收集状态，只提示缺失项；不得开始 OCR、图像理解、数据识别或优化诊断。

- 当前 `profile_id`。
- 原作品截图识别结果和用户确认后的标题、正文、全部图片内容。
- 每张图片保留 `image_index`、`ocr_text`、`visual_description`、`layout_description`、`image_role` 和 `unknowns`；`raw_parsed_content` 不进入生成上下文。
- 当前确认创作地图。
- 当前作品创作上下文：作品目标、读者预期、必须保留的内容、细化描写点和文笔风格。
- 当前账号已确认案例。
- 由`product_knowledge_ids`通过 [product-knowledge-registry.json](product-knowledge-registry.json) 精确解析出的相关产品初始知识正文。
- 用户本次要求。
- 用户确认的 `knowledge_usage_mode`：`knowledge_enhanced` 或 `deep_dive_only`。
- `knowledge_enhanced` 使用用户确认后的本轮知识使用清单；`deep_dive_only` 不使用本轮检索知识。
- 检索请求必须包含本轮确认的 `optimization_goals` 和 `target_metrics`，并返回细粒度知识单元、匹配查询、匹配词和排序理由。
- 目标指标统一为 `cover_click_rate`、`like_rate`、`collect_rate`；检索结果按指标、问题、内容位置和当前账号案例分组，并在知识不足时返回 `metric_gaps`。
- 产品知识单元应包含 `target_metrics`、`problem_types`、`content_positions`、`actions`、`mechanism`、`limitations` 和证据等级；私有案例应包含原始指标、优化目标、诊断、改动、发布后指标、变量和结论状态。
- 产品初始知识只提供指标诊断、内容方法、待验证指标和证据边界；本模块不设计或执行实验。`validation_metrics` 只表示建议发布后观察的指标，实验流程和案例沉淀由现有实验反馈系统负责。

作品优化目标、必须保留的内容和文笔风格均允许多选。除非用户主动要求排序，否则不得使用“最想”“优先”“主要目标”等措辞要求用户选出单一目标。

缺少已确认作品截图识别结果、当前确认地图或其他必需输入时，返回可操作错误，不生成部分确定性 Demo。

阶段A调用不得让模型自行猜测知识ID的含义。ID不存在、重复注册或无法取得正文时，调用器应在进入模型前返回输入错误；只把案例点名的知识条目传给模型。

## 工作步骤

创作深挖的自适应问题生成、自然语言归纳、素材来源分层和修改类型判断可以与本模块共享，但优化 Demo 不使用创作的内容蓝图替代原作品、目标指标或二维差异化门禁。技术深度和术语策略只在当前作品和优化目标需要时追问，不作为所有优化作品的固定字段。

用户提出修改后，先判断修改类型：标题/措辞等表现层修改可复用原检索快照；结构调整通常复用快照但需重新确认 Demo 结构；优化目标、目标指标、原作品、知识范围或事实素材变化属于事实层修改，必须重新检索并重新确认相关决策。

1. 将本轮目标归一化为点击率、点赞率或收藏率，并结合原作品数据诊断问题。
2. 根据原作品证据诊断问题，不编造原文、画面、数据或创作者经历。
3. 按“诊断 → 指标方法 → 内容位置 → 当前账号案例”分层检索；没有适用私有案例时不得伪造案例。
4. 完成相关性分析、排序和冲突处理，形成本轮知识使用清单并等待用户确认生成模式。
5. 知识决策确认后，生成2–3个“内容表达方向 × 专业化升级方向”候选；每个候选必须解释含义、与原作品的差异、适合解决的问题、对内容的影响、目标读者、技术术语/细节升级、通用表达与专业表达示例、可读性风险和待验证指标。
6. 专业化升级等级只允许通俗解释型、产品专业型、技术产品型；系统推荐2–3个等级，暂停等待用户分别选择或修改内容表达方向和专业化等级；未确认任一维度不得生成 Demo。
7. 根据用户确认的二维差异化方案，仅使用允许的知识与当前账号创作地图、当前作品创作上下文、原作品证据和用户本次要求重新组织内容。专业术语必须解释作用，不得为了术语密度编造技术事实。
   `knowledge_enhanced` 只能使用已确认 `knowledge_context`；`deep_dive_only` 不得使用本轮检索知识。
8. 生成且只生成一个完整主版本，可附少量局部备选。
9. 输出原文、新文和逐项 Diff；如果只有标题变化或结构差异不足，要求重新生成。
10. 输出标题、正文、话题、关键词、封面及每张图片的画面、构图、文字和信息层级建议。
11. 列出每项改动的“改动位置 → 目标指标 → 诊断问题 → 采用知识 → 具体动作 → 验证指标”，以及风险、待验证假设和不确定性。
12. 等待用户确认实际采用的改动；部分采用或自行修改时不得记为完全采用。

生成前后校验知识引用：知识增强模式的 `cited_knowledge` 必须是已绑定 `knowledge_context` 的子集；仅根据创作思路模式不得输出本轮知识引用。

### 完整内容硬性检查

`demo_ready` 前必须检查：`demo_copy.title` 是非空可发布标题；`demo_copy.body` 是完整正文而非目录、字段列表或“结构如下”的提纲；正文包含至少三个具体内容段落或等价的连续正文内容；`diffs` 和 `image_plans` 非空。检查失败时返回可操作错误，不向用户展示不完整 Demo。

## 原创、真实性与冲突

- 不复制参考内容的独特句式、故事、图片构图、文字排版或可识别内容顺序。
- 不编造身份、经历、产品功效、材料、耗时、数据或其他输入未提供的事实。
- 不承诺固定曝光、点赞或涨粉结果。
- 不把知识或案例中的相关性写成确定因果。
- 用户要求与当前有效地图、已确认案例、事实或安全边界冲突时，展示冲突和待确认取舍，不静默覆盖约束。

## 模块输出

在公共输出字段之外，输出：

```json
{
  "optimization_goal": ["click", "understanding"],
  "diagnosis": [],
  "original_copy": {},
  "demo_copy": {},
  "diffs": [],
  "keyword_suggestions": [],
  "topic_suggestions": [],
  "cover_plan": {},
  "image_plans": [],
  "change_items": [],
  "cited_knowledge": [],
  "expected_metrics": [],
  "uncertainties": [],
  "adoption_status": "pending"
}
```

`adoption_status`在用户确认前保持 `pending`。不得把生成的 Demo 或建议自动记为用户已采用。

差异化方案仅属于历史作品优化链路，不适用于原创创作。候选示例用于解释方向含义，不是最终文案；内容表达方向可包括“问题排查清单型”“产品经理自查框架型”和“项目决策流程型”，专业化等级可包括“通俗解释型”“产品专业型”和“技术产品型”。
